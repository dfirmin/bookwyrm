## Found and fixed

- **The MCP SDK is optional in Hermes.** Without it the GitHub server never connects and Bookwyrm
  starts with no GitHub tools (it said so rather than guessing). README setup now has a
  `hermes -p bookwyrm mcp test github` step.
- **`Warning: Unknown toolsets: mcp-github`** at start-up is harmless: printed before the MCP
  server connects. Documented.
- **No Docker:** `install.sh --github-mcp-bin <path>` wires the release binary in and keeps it
  across re-runs.

## Not proven here

- **The token as a fence.** This test environment routes GitHub calls through a proxy that
  substitutes its own credentials, so the fine-grained token's repo scope was not exercised.
  Branch protection and the tool allow-list were in force; the token's scope needs one check on
  a normal machine (a read of a repo outside its scope should fail).
- **Multi-turn confirmation.** Both runs were one-shot; run 2 was told up front not to read the
  note back. The read-back step in `record-sme-statement` needs an interactive run.
- Small corrections, quarantine and inbox intake: no quarantined drafts or published concepts
  existed on `main` to exercise them.
