# Live proof — voice companion, 2026-10-05

What was run for [ADR 0003](../adr/0003-voice-companion.md), on a 2-core Linux cloud box with
live Hermes (`claude-sonnet-5-5`, Bookwyrm profile, multiplexed gateway API) and live GitHub
reads of `archivist-knowledge-01`. No audio hardware: speech in was synthesized (a second
Kokoro voice), speech out was recorded.

## Hermes as the voice brain (runs API)

| Check | Result |
|---|---|
| First words, warm, with on-a-call instructions | 0.9–1.9 s |
| First words, cold (first call after start) | 9.3 s: why the app warms Hermes while it rings |
| Spoken-style answer | "Hi Dee. Let me check the repo for quarantine." then a short answer ending in a question |
| Same `session_id` across turns | remembered who was calling and the earlier gap answer |
| `POST /runs/{id}/stop` mid-answer | `run.cancelled` within 0.1 s |
| One slow model call | an Anthropic call took 29 s for 171 tokens; tools took 0.5 s |

## Scripted calls through the pipeline (`voice/tests/call_sim.py`)

Headset (no echo):

| | |
|---|---|
| Greeting after connect | 1.3–1.4 s |
| Caller stops → Hermes run starts | ~0.6 s |
| Caller starts talking over Bookwyrm → it stops | 0.3–0.5 s; interrupted Hermes run status `cancelled` |
| "Let me check the repo" | spoken before the lookup (flushed on `tool.started`) |
| Slow lookup | "Still looking." / "Bear with me, almost there." filled the silence |

Bugs found and fixed on the way: a missing helper in the STT service; the sentence splitter
holding "Let me check…" until after the tool; the test's own timing (it measured from when the
caller's line was *synthesized*, not spoken).

Speaker echo, raw (35% of Bookwyrm's voice back into the mic, no echo cancellation): Bookwyrm
interrupted itself, as expected. At 5% residue, two phantom fragments got through ("And there's no
marketing.", "to the social media"); `EchoGuard` now catches both and still passes ten things a
caller plausibly says (`voice/tests/test_units.py`). Real echo cancellation could not be tested
here.

## WebRTC

- Python client (`voice/tests/webrtc_call.py`) → server: greeting, question, answer. Transcribed
  back: "Hey Dee, what's up? Let me check the repo, Dee. There are six open issues right now…"
- **The real app renderer in Chromium** (`app/tests/e2e.js`, fake microphone): rang, connected,
  greeted, heard "How many open issues are there right now?", answered from GitHub, captions on
  the card once each. Found and fixed: Pipecat's JS transport fetched a script from
  `c.daily.co` at call time (replaced with a 120-line plain WebRTC client); every caption twice
  (`new` and `completed` events); first words clipped when spoken over the greeting (echo
  cancellation ducking: documented).
- Setup script run end to end in a fresh Hermes home; the service started from the installed
  `voice/.venv`, read Bookwyrm's API key and GitHub token from the profile's `.env`, and the app
  call above was repeated against it.

## Not proven here

Talking over Bookwyrm on a MacBook's own speakers (echo cancellation); latency on Apple
Silicon; the macOS microphone permission flow; the dragon's animations at full frame rate.
